Build a complete production-quality responsive web application called "Haven".

Haven is a discreet women's safety, wellbeing, mental-health and emergency-support platform. It should feel like a premium modern wellness/lifestyle application rather than an obvious emergency app.

TECH STACK
- React
- TypeScript
- Vite
- Tailwind CSS
- Supabase for authentication/database/storage/realtime
- GSAP for subtle animations
- Lucide React icons
- React Router
- PWA support so it can be installed on a phone

The application must be mobile-first but look excellent on desktop and tablet.

==================================================
DESIGN DIRECTION
==================================================

The UI must be extremely clean, minimalist and natural.

Avoid:
- stereotypical bright pink women's safety design
- huge gradients everywhere
- excessive animations
- clutter
- childish illustrations
- giant SOS buttons dominating every screen

Use:
- warm neutral background
- off-white / cream surfaces
- charcoal text
- muted sage / dusty rose accents
- rounded cards
- subtle shadows
- generous spacing
- excellent typography
- large touch targets
- bottom navigation on mobile
- sidebar/navigation on desktop

Animations should use GSAP but remain subtle:
- page entrance animations
- staggered card reveals
- smooth navigation transitions
- SOS interaction animation
- modal transitions
- expanding/collapsing cards
- subtle number/count animations

Respect prefers-reduced-motion.

The app should feel trustworthy, private, calm and premium.

==================================================
EMERGENCY / SOS SYSTEM
==================================================

Create a serious emergency system.

The SOS button should require press-and-hold for approximately 2 seconds to reduce accidental activation.

After activation:

1. Obtain current browser geolocation WITH explicit permission.
2. Create an emergency event in Supabase.
3. Display current coordinates and map link.
4. Show trusted contacts.
5. Provide quick call actions.
6. Provide quick message actions.
7. Start an emergency screen.
8. Allow the user to cancel false activation.
9. Store emergency event history.
10. Allow periodic location updates while the emergency session is active and the app/browser permits it.

IMPORTANT:
Do NOT pretend the web app can silently track someone in the background when the browser/OS does not allow it.

Clearly show whether location sharing is:
ACTIVE
PAUSED
UNAVAILABLE

Never collect location without explicit consent.

AI SUPPORT CHAT
==================================================

Create a conversational support assistant.

IMPORTANT:
Do NOT present it as a licensed therapist.

Name it something such as:

Haven Companion

Description:

"A private AI space for reflection and emotional support. It isn't a replacement for professional mental-health care."

Interface should resemble a clean modern messaging app.

Provide conversation starters:

"I need to talk."
"I'm feeling anxious."
"Help me think through something."
"I don't feel safe."
"I had a difficult day."

Create API abstraction:

/api/chat

Keep provider configuration separate so an LLM API can later be connected securely server-side.

NEVER expose API keys in frontend code.

The AI support system should have safety escalation logic.

If the user indicates immediate physical danger:
prioritize emergency resources and trusted contacts.

If the user expresses self-harm intent:
show appropriate crisis-support guidance and encourage contacting emergency/professional support.

Do not allow the AI to diagnose mental illnesses.

IMPORTANT SECURITY RULES
==================================================

This application handles extremely sensitive information.

Therefore:

Never expose service-role keys to frontend.

Never store passwords manually.

Use Supabase Auth.

Use Row Level Security.

Request geolocation only when necessary.

Never activate tracking without user permission.

Allow location sharing to be stopped immediately.

Do not claim SMS/calling/background tracking capabilities unless they actually exist.

Sanitize user-generated content.

Validate file uploads.

Restrict attachment file types and sizes.

Do not log journal/chat/location contents unnecessarily.
